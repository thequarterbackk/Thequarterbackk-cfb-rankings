How the model works

1. Core performance

Base Rating = (Wins × 100) + Points For − (Points Allowed × 1.5). The model rewards winning and scoring while explicitly punishing teams for giving up points. There is no margin cap.

2. Dynamic Win Validation

An opponent's value does not remain permanently frozen and does not decay merely because time passes. Instead, the model asks whether that opponent's later performances validate how strong they appeared when the game was played.

Effective Opponent Strength = 60% × Strength When Played + 40% × Later Validated Strength

3. Quality adjustment

Wins receive positive opponent-quality value. Losses are penalized more severely when they come against weaker opponents. A highly rated opponent that continues to perform well preserves the value of an earlier win; an opponent that collapses can reduce that value. An underrated opponent that later proves strong can increase the value of the earlier result.

4. Week-to-week memory

The rating entering each week is frozen as that week's original opponent strength. Later games validate that historical value instead of simply replacing it with today's ranking.

5. Live results

The public site never receives the private CFBD API key. A GitHub Action checks for newly completed games, recalculates the model after finals, rewrites the public data file, and GitHub Pages republishes it automatically.

6. CFP Ownership Map

The map begins with county-level territory based on geographic proximity. A team's empire is made of the territory units it currently owns. When that team loses, every territory unit it owns transfers to the winner. Split starting counties are shown with multiple colors until those shares consolidate through game results.
